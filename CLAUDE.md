# CLAUDE.md — Правила для Claude Code (rcdesk)

> Правила обязательны для всех взаимодействий. ARCHITECTURE.md — архитектурные
> решения и стек. SLICES_LOG.md — состояние проекта и история слайсов.

## Что это

rcdesk — удалённый доступ к рабочему столу через браузер (Safari, Chrome).
Хост-агент на Rust для macOS и Windows, транспорт WebRTC, веб-клиент на TypeScript,
сигнальный сервер на Rust. Аудитория: владелец и небольшая команда. Домен `rcdesk.app`.

## Режим работы: архитектор-оркестратор + субагент-исполнитель

Главный чат — **архитектор** (Fable/Opus). Мясные под-шаги исполняет субагент
**`executor`** (Sonnet, `.claude/agents/executor.md`) через Agent tool. Владелец
подключается на трёх точках: **развилки**, **«go»**, **«коммит»**.

### Разделение ролей

- **Архитектор:** держит контекст (сначала «📍 голова» SLICES_LOG.md — состояние и
  открытые долги; затем ARCHITECTURE.md). Делает разведку, планирует, формулирует
  точные промпты исполнителю, сверяет его diff, коммитит после одобрения.
  НЕ доверяет памяти о контракте — берёт его из фактического кода (`proto/`).
- **Исполнитель (`executor`):** получает ОДИН узкий промпт (скоуп + acceptance +
  команда прогона + baseline), читает реальный код, пишет, гоняет проверки,
  возвращает результат. Скоуп не расширяет.

### Цикл одного под-шага

1. **Разведка** (read-only): фактический код/контракт на сверку. Без кода.
2. **План под-шага:** структура + решения + список тестов. Открытые вопросы —
   **развилки**, выносятся владельцу явным списком, не угадываются.
3. Ждём **«go»** (или правок решений).
4. **Исполнение:** точный промпт субагенту `executor`.
5. **СВЕРКА diff против промпта** (обязательна, см. ниже).
6. Итог владельцу: точные строки гейтов + `git diff --stat`. Ждём **«коммит»**.
7. Один коммит. Push — за владельцем, пока он явно не разрешит архитектору.

### Обязательная сверка вывода субагента

Внешнего ревьюера нет, поэтому перед «жду коммит» архитектор сверяет diff:
- изменены ровно файлы из скоупа, чужой скоуп не тронут;
- нет отсебятины: лишних зависимостей, переименований, «заодно» рефакторингов;
- гейты сходятся с ожиданием (точные строки, не арифметика «было+N»);
- acceptance выполнен дословно.
При расхождении — не коммит, а фикс-промпт или развилка владельцу.

### Жёсткие правила процесса

- **PLAN-MODE.** Действие за рамками промпта = ПАУЗА и доклад.
- **Один под-шаг = один коммит.** Правка чужого скоупа — отдельный fix-коммит.
- **Разведка ПЕРЕД кодом.** Контракт сообщений — из `proto/`, не из памяти.
- **Нет новых зависимостей без решения архитектора.** Каждый крейт/пакет в
  `Cargo.toml`/`package.json` — осознанное решение, записанное в ARCHITECTURE.md.
- **Платформенный код — за `cfg`-границей.** macOS/Windows-специфика живёт в
  `host/src/platform/{macos,windows}/`, общий код не знает о платформе.
- **Производительность — измеряется, не предполагается.** Любая оптимизация
  видеопути сопровождается цифрой (fps, мс, Мбит/с) в SLICES_LOG.
- **Коммиты:** на русском, глагол в инфинитиве, subject ≤72 символа, префиксы
  `feat/fix/refactor/docs/test/chore/ci`. Атрибуция в конце сообщения — по
  правилам сессии.
- **Взаимодействие:** не переспрашивать одно и то же; «готово/ок/закрыто» — этап
  закрыт; статус — `git status --short` + `git diff --stat`.

## Гейты (команды проверки)

Запускать из корня репозитория. Приводить ТОЧНЫЕ итоговые строки.

```
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cd web && npm run check && npm test && npm run build
```

- Rust toolchain — stable из rustup (`~/.cargo/bin`). Локальная сборка — macOS arm64.
- Windows-сборка — в CI (`windows-latest`) и на тестовом ПК владельца (Windows 10 x64).
- Ручная проверка видеопути (fps/задержка) — отдельно, по инструкции слайса.

## Контекст и жизненный цикл чата

- Субагент `executor` эфемерен: каждый вызов — свежий контекст, ничего не копит.
- Архитектор копит контекст сознательно. Один чат = один слайс/под-слайс.
  Новый чат начинается на закрытии слайса, после docs-коммита и обновления
  SLICES_LOG: состояние поднимается из доков без потерь.
- При старте чата архитектор ПЕРВЫМ читает «📍 голову» SLICES_LOG.md, затем
  ARCHITECTURE.md — и только потом действует. Голову держит актуальной.

## Протокол при выявлении просчёта прошлого этапа

**Архитектор решает сам (механика):** мелкий фикс чужого огреха отдельным
fix-коммитом в пределах одобренного скоупа; занесение долга в SLICES_LOG.

**Архитектор выносит владельцу (направление):** вставка нового под-шага/слайса;
«чинить сейчас vs долг», если фикс выходит за скоуп; смена порядка слайсов.

Формат: **проблема → варианты → рекомендация → жду решения.** Не раздувать план
молча, не поручать субагенту «заодно поправить».
