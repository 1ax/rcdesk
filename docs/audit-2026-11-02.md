## 1. Высокий приоритет

### S-1. Сервер: параллельный Argon2 без ограничения → OOM контейнера (DoS)
`server/src/ws.rs:1289-1318` (`PasswordLogin`), аналогично `:1353-1391` (`EmailChange`).
`login_limiter.check(ip)` токен не списывает; `spend` — только после `verify_password_blocking().await`,
то есть после десятков миллисекунд Argon2 (`accounts.rs:64,73` `Argon2::default()` ≈ 19 МиБ на хеш).
Пул `spawn_blocking` до 512 потоков, лимита WS-соединений нет (`main.rs:36`, в nginx нет `limit_conn`).
Сценарий: 30–50 соединений с одного IP, в каждом `PasswordLogin` со случайной почтой — все проходят
`check`, 0,6–1 ГБ против `mem_limit` 256M (`docker-compose.prod.yml:34-36`) → OOM-kill → все хосты
отваливаются. Повторяемо.
**Фикс:** глобальный `tokio::sync::Semaphore` на 2–4 permit вокруг hash/verify; списывать токен
лимита до вычисления и возвращать при успехе.

### H-1. Хост: пароль доступа fail-open — любая ошибка чтения `access.json` = «пароля нет»
`host/src/access.rs:219-255` — `load()` возвращает `None` и при `NotFound`, и при `PermissionDenied`/
sharing violation/битом JSON (только `warn`). `signaling/mod.rs:1689` — `if access_store.load().is_some()`
→ иначе сеанс без OPAQUE и без привязки DTLS, по одному PIN.
Сценарии: macOS полный режим — `access.json` `root:admin 0660` в каталоге `2770`, второй пользователь
не из группы admin → файл не читается → пароля «нет»; Windows — антивирус/индексатор держит файл в момент
чтения → один сеанс без пароля. `password status` тем же путём скажет «пароля нет».
**Фикс:** `load() -> Result<Option<_>>` (`NotFound` = `Ok(None)`, остальное = `Err`); в `PeerJoined`
при `Err` — `Bye` с причиной и `error!`. Тот же шаблон в `device.rs:118-141` (M-1 ниже).

### W-1. Веб: защита «хост требует пароль» (E2) обходится сервером-посредником
`web/src/app.ts:3247` — `deviceId = msg.device_id` из `joined`, т.е. значение выбирает сервер;
флаг `rcdesk.authRequired.<deviceId>` ставится по `auth_required` (`:3352`) и проверяется на `offer`
(`:3430-3436`). Подменный сервер отвечает `joined{device_id:"Y"}`, не пересылает `auth_required`, шлёт
`offer{auth:null}` — флага для `Y` нет, DTLS-привязка пропускается. При первом входе по PIN защиты нет вовсе
(нет TOFU).
**Фикс:** для `connect_device` запоминать запрошенный `device_id` и сверять с `joined.device_id`
(расхождение → `bye`); для PIN — TOFU по первому `auth_required`; дальше — закрепление отпечатка DTLS
хоста по `device_id`.

### I-1. Вендорные патчи `rtc-sctp`/`rtc-turn` могут молча перестать применяться
`Cargo.toml:39-42` (`[patch.crates-io]` на `vendor/`), `Cargo.toml:4` (`exclude = ["vendor"]`),
`.github/dependabot.yml` разрешает минорные обновления `rtc`/`webrtc`. Патч-копии версии `0.20.5`;
если `rtc` 0.20.6 потребует `rtc-sctp ^0.20.6`, патч перестанет подходить — cargo лишь пишет
`warning: Patch ... was not used`, CI зелёный (`-D warnings` на это не действует). В релиз уедет апстримный
SCTP с MTU 1228 / T3-rtx=5 — вернётся баг «канал хост→клиент встаёт» (`vendor/rtc-sctp/RCDESK-PATCH.md`).
Тесты патчей (`rcdesk_patch_tests::*`) в CI не гоняются (каталог вне workspace).
**Фикс:** шаг CI `cargo tree -i rtc-sctp | grep -q vendor/rtc-sctp` (и для `rtc-turn`, `scap`) + падение на
`was not used`; `cargo test --manifest-path vendor/rtc-sctp/Cargo.toml --lib` отдельным job; `ignore` на
`rtc*`/`webrtc*` в Dependabot до D72.

### V-1. Хост: блокирующая сборка захвата и кодера на tokio-воркере
`host/src/signaling/mod.rs:964-989` — `async fn VideoPipeline::start` синхронно зовёт
`(ctx.build_source)(…)` (`Capturer::build` + `start_capture` SCK/WGC) и `build_encoder` (MFT enum/
activate, `VTCompressionSessionCreate`). Вызывается при старте сеанса, `SelectDisplay` (`:2959`) и шторке
(`:3043`). На Win10/HD 4600 инициализация MFT — сотни мс–секунды; воркер с сигналингом и RTCP стоит.
Побочно: `MediaFoundationEncoder::new` делает `CoInitializeEx` (`mediafoundation.rs:129`) без парного
`CoUninitialize`. `replace_pipeline` стартует новый конвейер до остановки старого (`:2959` vs `:2983`) —
два кодера/источника одновременно.
**Фикс:** `spawn_blocking` вокруг `build_source + build_encoder`; rate-limit `SelectDisplay`.

### V-2. Хост: смена разрешения/дисплея посреди сеанса и отсутствие watchdog
`capture/scap.rs:256-267` (SCK: `Err` → `VideoFailed` → конец сеанса), `encode/mediafoundation.rs:645-650`,
`videotoolbox.rs:401-406` (кадр другого размера → `Err`), `capture/gdi.rs:134-148` (размер фиксирован в
`new`: после смены режима картинка обрезана, ошибки нет), `input/mod.rs:290` + `signaling/mod.rs:2994`
(`CaptureRect` обновляется только в `replace_pipeline` → клики со смещением). Детектора «captured растёт,
encoded нет N с» нет — повисший `ProcessInput`/`BitBlt` (TDR, сон) D58 не ловит.
**Фикс:** сравнение `list_displays()` раз в 2 с (или `WM_DISPLAYCHANGE`/
`CGDisplayRegisterReconfigurationCallback`) → `replace_pipeline` тем же id + обновление `CaptureRect`;
watchdog в `run_adapt_task` → перезапуск конвейера.

## 2. Средний приоритет

### Сервер
- **S-2. Нет дедлайна на Hello и лимита соединений.** `ws.rs:182-215` — Ping/Pong сбрасывает
  `read_timeout`; соединение без Hello живёт вечно. Нет лимита частоты сообщений на соединение
  (`ClientAuth{bad}`, `PasskeyLoginStart`, `EmailCodeRequest` — по DB-чтению каждое). Фикс: дедлайн 10–15 с
  на Hello, 60 с на аутентификацию, Ping учитывать после аутентификации; `limit_conn` в nginx; токен-бакет
  сообщений.
- **S-3. Слияние анонимного владельца теряет `wake_devices`.** `db.rs:900-927` `merge_anonymous_owner`
  переносит `ownership` и `sessions`, затем `DELETE FROM owners` → каскад (`db.rs:1296`) сносит ручные
  устройства и роутеры-будильники (с `token_hash`). Пользователь без аккаунта добавил роутер → вошёл в
  аккаунт → роутер молча получает 401 на `/wake/poll`. Тесты `merge_anonymous_owner_*` это не проверяют.
  Фикс: `UPDATE wake_devices SET owner_id=?2 WHERE owner_id=?1` в транзакции + тест.
- **S-4 / M-3. `X-Real-IP` доверяется любому пиру.** `ws.rs:53-60`. Для прода — решение (порт на
  127.0.0.1, nginx переписывает), но LAN-хаб (`host/src/hub/mod.rs`, `0.0.0.0:8443`) использует тот же
  `lan_hub_app` — любой клиент LAN подделывает IP и обходит ведро PIN (остаётся только глобальное:
  300 залпом, 1 в 2 с). Фикс: параметр `trust_proxy_headers`, у хаба `false`.
- **S-5. TURN TTL 24 ч** (`ice.rs:18`, `.env.prod.example:18`) — остаток S-H3: креды после `Bye`
  валидны сутки, бесплатный UDP-релей. Фикс: `RCDESK_TURN_TTL_SECS=7200`.
- **S-6. Выжигание попыток чужого email-кода.** `accounts.rs:204-217` — 5 неверных кодов на чужую
  почту гасят её активный код; не привязано к IP. Фикс: попытки на пару (почта, IP) или замедление вместо
  блокировки.
- **S-7. Passkey: состояние церемонии без TTL и `owner_id`** (`ws.rs:1448-1449, 1607-1616`), нет лимита
  частоты и числа passkey на владельца. Остаток прошлого аудита.
- **S-8.** Вытесненное соединение хоста не убивается и не сверяется по `Tx` (`ws.rs:398-415`,
  `registry.rs:~615-660`) — старое соединение с теми же кредами может слать Offer/ICE и закрыть сеанс `Bye`.
- **S-12.** Отравленный мьютекс (`expect` в `registry.rs`, `db.rs`) → `/healthz` 503, но
  `restart: unless-stopped` на unhealthy не реагирует. Фикс: `panic = "abort"` в release-профиле сервера.
- **S-13.** `db.rs:1317` — старый бинарник открывает БД более новой схемы молча. Фикс: `version >
  SCHEMA_VERSION` → ошибка.

## 6. Что сделано хорошо
- Сервер: SQL параметризован целиком, секреты только SHA-256, фиктивный хеш выравнивает время ответа,
  ownership проверяется последовательно (канал/`host_id`/`session_id`), ротация PIN и bounded-очереди с
  тестами, миграции транзакционные с `foreign_key_check`.
- Хост: OPAQUE + HMAC-привязка DTLS в обе стороны с детерминированными тестами; `serde` без `unwrap` на
  входящих; файлы — `create_new`, part + rename, санитайзер, симлинки не архивируются, `FsUser` fail-closed;
  обновление — подпись до разбора JSON, два ключа, `issued_at`, анти-даунгрейд; `SAFETY`-комментарии и
  освобождение на всех путях ошибки в MF/VT/GDI; `FrameSlot`/`Pacer`/поколения конвейера.
- Веб: данные сервера и хоста нигде не попадают в `innerHTML`; проверки `session !== currentSession`
  после каждого `await`; центральная уборка таймеров/слушателей; устойчивость к недоступному
  `localStorage`; 560 тестов, у ключевых модулей тесты крупнее кода; без фреймворков, без inline-стилей.
- Инфра: минимальные `permissions`, пин по SHA, `workflow_call`, `read_only`/`cap_drop`/`mem_limit`,
  `--locked` в Dockerfile, HEALTHCHECK, бэкап с `integrity_check`+GPG+heartbeat, CSP без `unsafe-inline`,
  `immutable`/`no-cache` по месту, установщики с продуманным обновлением поверх.
