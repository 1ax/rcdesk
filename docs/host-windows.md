# Хост на Windows 10 (тестовый стенд)

## Установка

Проще всего -- установщик. Скачать `rcdesk-setup.exe` из GitHub Releases:
<https://github.com/1ax/rcdesk/releases/latest> и запустить.

**SmartScreen.** Установщик не подписан, поэтому Windows покажет «Windows
защитила ваш компьютер»: нажать «Подробнее» → «Выполнить в любом случае».

**Для всех или только для меня.** В начале установщик спрашивает:

- «для всех пользователей» -- Program Files, нужен UAC, доступны оба режима
  ниже;
- «только для меня» -- `%LOCALAPPDATA%\Programs\rcdesk`, без UAC, всегда
  обычный режим (служба Windows без администратора невозможна).

**От какого пользователя запускать.** Двойным кликом из Проводника, от того
пользователя, у которого должен работать агент. При «только для меня» UAC не
появляется ни у администратора, ни у обычного пользователя -- rcdesk ляжет в
профиль запустившего. При «для всех» UAC может спросить пароль другого
администратора -- автозапуск и агент всё равно настроятся у исходного
пользователя. **Не запускать** через «Запуск от имени администратора» или из
консоли администратора: исходного пользователя тогда нет, и автозапуск с
агентом окажутся у администратора. Повторный запуск (обновление) вопрос «для
всех / для меня» не задаёт, а повторяет прошлый выбор; чтобы его сменить,
сначала удалить rcdesk.

**Режимы** (страница выбора только при установке для всех):

- *Обычный* (по умолчанию) -- агент в трее (`rcdesk-agent.exe`), запускается
  при входе в Windows; ярлык «rcdesk» в меню «Пуск». Окна администратора не
  управляются (см. «Окна с правами администратора»).
- *Полный* -- служба Windows `rcdesk` (LocalSystem): управление окнами
  администратора и работа до входа в систему. Агент при работающей службе сам
  завершается, ярлыка и автозапуска нет. Журнал службы:
  `%ProgramData%\rcdesk\logs\service.log`.

**Обновление.** Запустить новый `rcdesk-setup.exe` поверх: установщик
останавливает службу и закрывает агентов (у всех пользователей), заменяет
файлы и возвращает прежний режим; при повторной установке для всех режим
можно сменить на странице выбора. Если служба уже стоит, обновлять нужно
установкой «для всех».

**Удаление.** «Параметры → Приложения» (или «Установка и удаление программ»)
→ rcdesk. Служба удаляется, агенты закрываются, значение автозапуска
убирается. **Данные остаются**: `%LOCALAPPDATA%\rcdesk` (ключ устройства,
пароль доступа, логи агента) и `%ProgramData%\rcdesk` (то же для службы) --
при необходимости удалить вручную.

## Требования

Windows 10 версии 1903 (сборка 18362) или новее, x64 (захват — Windows
Graphics Capture, ввод — SendInput). Права администратора не нужны (кроме
установки «для всех» и полного режима).

## Без установщика

Ручной путь: распаковать zip и запускать из консоли (всё ниже в этом файле).

## Запуск

Всё из консоли (cmd или PowerShell), из каталога с exe.

```
rcdesk-host.exe --version
```

```
rcdesk-host.exe list-displays
```

Список мониторов, колонки через табуляцию: `id  title  WxH@x,y  primary|-`.
`serve`/`bench` принимают `--display <id>` с этим id, чтобы захватывать
конкретный монитор; без флага — основной (primary). `id` — это HMONITOR,
он может смениться при переподключении монитора или перезагрузке, поэтому
зашивать `--display` в автозапуск не стоит -- лучше оставлять дефолт (primary)
или проверять `list-displays` перед стартом.

```
rcdesk-host.exe bench --seconds 5
```

Захват+кодирование без сети; напечатает `captured/encoded/dropped/keyframes`,
`avg_fps`, `avg_bitrate_kbps`. Эти цифры нужны для журнала.

```
rcdesk-host.exe bench --seconds 5 --capture gdi
```

То же самое, но принудительно через GDI-бэкенд (см. «Бэкенды захвата» ниже) —
замер на железе/ВМ, где WGC недоступен.

```
rcdesk-host.exe bench --seconds 5 --encoder mediafoundation
rcdesk-host.exe bench --seconds 5 --encoder openh264
rcdesk-host.exe bench --seconds 5 --max-qp 30
```

Сравнение кодеров (см. «Кодеры» ниже). Первая строка вывода — `encoder=…`,
последняя — `avg_capture_to_encoded_ms`/`p95_…` (задержка от захвата кадра до
готового H.264). Отдельно печатаются средние размеры ключевых и дельта-кадров
(`avg_keyframe_bytes`/`avg_delta_bytes`).

```
rcdesk-host.exe serve --server wss://rcdesk.app/ws --no-input
```

Первый сеанс без ввода: напечатает `PIN: NNNNNN`, дальше открыть
https://rcdesk.app в браузере на другом устройстве, ввести PIN.

```
rcdesk-host.exe serve --server wss://rcdesk.app/ws
```

Полный режим с мышью и клавиатурой.

**⚠️ Подключившийся клиент реально управляет этим ПК** — как только сессия
установлена, движения курсора, клики и нажатия клавиш в браузере клиента
реально выполняются на машине, где запущен `rcdesk-host.exe`.

Подробные логи:

PowerShell:

```
$env:RUST_LOG="debug"; .\rcdesk-host.exe serve ...
```

cmd:

```
set RUST_LOG=debug
rcdesk-host.exe serve ...
```

## Бэкенды захвата

`--capture auto|wgc|gdi` у `bench` и `serve` (по умолчанию `auto`):

- **WGC** (Windows Graphics Capture, через `scap`) — нужен видеодрайвер с
  поддержкой Direct3D 11 (feature level ≥ 11_0). `auto` выбирает его, когда
  пробное создание Direct3D-устройства (`platform::windows::d3d::wgc_supported`)
  это подтверждает.
- **GDI** (`BitBlt`) — работает на любом железе и в ВМ, включая легаси-драйверы
  ниже Direct3D 11 (обнаружено на тестовом стенде: ATI Radeon HD 4600, только
  Direct3D 10.1, драйвер WDDM 1.1 — с этим драйвером `windows-capture` 1.4.4
  падает с паникой, поэтому `auto` заранее проверяет уровень поддержки и уходит
  на GDI сам). Выше нагрузка на CPU, курсор не попадает в кадр так же, как и у
  WGC, без «жёлтой рамки» (её рисует только WGC).

`--capture wgc`/`--capture gdi` форсируют бэкенд вне зависимости от того, что
показала проверка.

## Кодеры

`--encoder auto|openh264|videotoolbox|mediafoundation` у `bench` и `serve`
(по умолчанию `auto`):

- **mediafoundation** — H.264 MFT Media Foundation; **это и есть `auto` на
  Windows**: аппаратный MFT (Quick Sync, NVENC, AMF), если найден, иначе
  программный «H264 Encoder MFT» Microsoft. На стенде (ATI Radeon HD 4600,
  аппаратного MFT нет) программный Microsoft обходит openh264 по всем
  измерениям: `bench` захват→кодер 27 мс против 67–78, под видео в сеансе
  20–23 fps против 13–17 при устойчивом jitter-буфере 27–41 мс, текст при
  наборе чёткий. В логе: `media foundation encoder name=… hardware=false`.
- **openh264** — программный запасной кодер, есть везде; на Windows берётся,
  только если MFT не создался, или по явному `--encoder openh264`.
- **videotoolbox** — только macOS, на Windows отвечает ошибкой «not available».

`--max-qp N` (0..=51) — потолок QP кодера: ограничивает худшее качество кадра,
битрейт при этом может превышать целевой. Без флага у openh264 потолок 30
(без него дельта-кадры идут при QP > 34 и текст при наборе размыт), у
Media Foundation и VideoToolbox потолка нет. Замер на стенде для openh264:
без потолка под видео 0.4–2.1 Мбит/с и мягкий текст; с потолком 30 текст
чёткий, под видео 2.1–3.5 Мбит/с, но jitter-буфер растёт до 80 мс за
полминуты — кодер на этом CPU не успевает за 1080p, адаптация — слайс 2.3.

## Брандмауэр Windows

При первом сеансе появится запрос «Брандмауэр Защитника Windows заблокировал
некоторые функции этого приложения» — разрешить для частных сетей (WebRTC
слушает UDP на случайном порту для ICE). Без разрешения соединение может
пойти только через TURN или не установиться.

## Окна с правами администратора

В лёгком режиме (без установленной службы) `rcdesk-host.exe`/`rcdesk-agent.exe`
работает в контексте обычного пользователя. Когда на экране активно окно
процесса, запущенного с более высокими правами (например, Диспетчер задач
через «Запуск от имени администратора», или любой UAC-диалог) — Windows
защищает его через UIPI (User Interface Privilege Isolation) и молча
отбрасывает инъекцию `SendInput` из менее привилегированного процесса.
Клики и нажатия клавиш при этом визуально «пропадают»: `SendInput`
возвращает успех, в логе хоста ничего не появляется, само окно никак не
реагирует.

Хост следит за активным окном (опрос раз в секунду,
`platform::windows::elevation::foreground_input_blocked`, слайс 2.6e) и при
смене состояния шлёт клиенту `control: InputBlocked { blocked, reason }`.
Клиент показывает баннер «Окно администратора: Windows не пропускает ввод» с
причиной и **продолжает слать ввод как обычно** — баннер только
предупреждает, не отключает управление (в отличие от `InputStatus`,
означающего полное отсутствие инжектора на весь сеанс). Это даёт
пользователю возможность кликнуть мимо заблокированного окна и вернуть
фокус на что-то, чем можно управлять.

Лечится полным режимом (служба SYSTEM, слайс 4.1a, раздел ниже): помощник
работает как SYSTEM, и UIPI его ввод в окна администратора не останавливает
(проверено на стенде 2026-10-10 на Диспетчере задач). Окна UAC с затемнением
экрана, экран блокировки и вход в Windows живут на отдельном рабочем столе
`Winlogon` — в полном режиме они пока не транслируются (долг 4.1b).

## Что известно и не считается ошибкой

- Жёлтая рамка вокруг экрана на время сеанса при бэкенде **WGC**: её рисует
  Windows Graphics Capture; на Windows 10 отключить нельзя (API
  `IsBorderRequired` появился в сборке 20348, то есть в Windows 11), к тому же
  scap 0.0.8 не даёт настроить. Долг в SLICES_LOG. При бэкенде **GDI** рамки
  нет вовсе (см. «Бэкенды захвата»).
- Курсор в видео не попадает — его форму хост шлёт отдельно, браузер рисует
  локально.
- Без `--display` захватывается основной (primary) монитор; переключение — селектором в клиенте (слайс 2.4).

## Что смотреть при проблемах

- `serve` завершился сразу с ошибкой про WebSocket/TLS → проверить доступ к
  https://rcdesk.app из браузера на этом же ПК.
- В браузере «connecting» дольше 10 с → брандмауэр.
- Видео есть, ввод не работает → запущено с `--no-input`.
- Видео есть, клики по конкретному окну не доходят, в клиенте баннер «Admin
  window» → см. «Окна с правами администратора» выше.
- В логах `rtc_dtls` WARN «Unsupported Extension» и mDNS-таймауты — шум, не
  ошибка (долг D12).

Ctrl+C в консоли.

## Агент в трее (`rcdesk-agent.exe`)

Второй бинарник, тот же пакет: хост как фоновая программа со значком в
системном трее вместо консольного процесса (слайс 2.6c). Лежит рядом с
`rcdesk-host.exe` в том же архиве. Запуск — двойным кликом или из
проводника; окна консоли не открывается (`windows_subsystem = "windows"`).

Значок в трее — статус (PIN / активная сессия / офлайн), меню: «Копировать PIN»,
«Завершить сеанс», «Открыть лог» (открывает лог в Блокноте), «Выйти из rcdesk».

Лог — файл `%LOCALAPPDATA%\rcdesk\logs\agent.log` (ротация в `agent.log.1`
при размере больше 5 МБ), не консоль. Второй запущенный экземпляр сразу
завершается (лок-файл `%LOCALAPPDATA%\rcdesk\agent.lock`).

## Автозапуск при входе

Выключен по умолчанию, прав администратора не требует. Включить — пунктом
меню трея «Запускать при входе» либо командой:

```
rcdesk-host.exe autostart on
rcdesk-host.exe autostart status
rcdesk-host.exe autostart off
```

Механизм — значение `rcdesk` в
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` (путь к
`rcdesk-agent.exe` в кавычках), правит его только сам `rcdesk-host.exe` /
пункт меню агента. Запись видна в Диспетчере задач → вкладка «Автозагрузка»
(имя `rcdesk`) — но для полного выключения используйте `autostart off` или
пункт меню, а не кнопку «Отключить» там: она гасит запуск, не трогая само
значение в реестре, так что `autostart status` после неё всё ещё покажет
`on`.

## Полный режим: служба Windows (слайс 4.1a)

Служба `rcdesk` (LocalSystem, автозапуск до входа) сама экран не захватывает: раз в
секунду она смотрит активную консольную сессию и держит в ней помощника
`rcdesk-host.exe serve --machine`, запущенного с токеном SYSTEM в этой сессии
(`winsta0\default`). Сменилась сессия (выход, вход, смена пользователя) — помощник
перезапускается в новой; упал — перезапуск через 1–30 с. Помощник умирает вместе со
службой (Job object).

Все команды — из cmd **от имени администратора**:

```
rcdesk-host.exe service install            :: установить и запустить (по умолчанию wss://rcdesk.app/ws)
rcdesk-host.exe service install --server wss://…/ws
rcdesk-host.exe service status             :: состояние, PIN, пути
rcdesk-host.exe service stop
rcdesk-host.exe service start
rcdesk-host.exe service uninstall          :: остановить и удалить; данные остаются
```

- **Данные и логи** — `C:\ProgramData\rcdesk\` (доступ только SYSTEM и
  Administrators): `device.json`, `access.json`, `pin.txt`, `logs\service.log`,
  `logs\helper.log`. Читать — из cmd администратора (`type …`).
- **Устройство то же:** `install` копирует `device.json` и `access.json` из
  `%LOCALAPPDATA%\rcdesk\` установщика, компьютер в «Моих компьютерах» не меняется,
  пароль сохраняется.
- **Пароль:** при установленной службе `rcdesk-host.exe password set|clear|status`
  работает с `C:\ProgramData\rcdesk\` и требует cmd администратора.
- **PIN** нужен только для первой привязки: `service status` (может показать
  устаревший, если помощник сейчас не на связи).
- **Трей:** в полном режиме значка нет — меню от процесса SYSTEM открывало бы окна с
  правами SYSTEM. `rcdesk-agent.exe` при работающей службе сразу выходит (в
  `agent.log`: «служба rcdesk работает (полный режим), агент не нужен»), так что
  автозапуск лёгкого режима можно не выключать.
- **Файлы** принимаются в «Загрузки» пользователя, вошедшего в консольную сессию
  (слайс 4.1d). Если сеанс начался на экране входа, передача файлов в нём выключена —
  переподключитесь после входа.
- **Exe службы** — тот, из которого выполнен `install`. Обновление: `service stop`,
  заменить exe, `service start`. ⚠️ Каталог с exe не должен быть доступен на запись
  обычным пользователям (иначе подмена exe = права SYSTEM): на стенде это `d:\rc`,
  что допустимо только для стенда; штатное место — Program Files (инсталлятор, 4.3).
- **Не работает пока (долги 4.1b/4.1c):** экран блокировки и входа, окна UAC с
  затемнением, Ctrl+Alt+Del — картинка в эти моменты чёрная/замершая, ввод туда не
  доходит.
- **Откат в лёгкий режим:** `service uninstall`, затем запустить `rcdesk-agent.exe`.
