# Живая проверка D76 (abs-send-time) на Mac, клиент Chrome

Цель: убедиться, что с abs-send-time REMB браузера стал настоящим (`remb_kbps`
в `5s summary` выше пола 50 и порядка реального канала) и что контроллер не
пилит битрейт по `reason="remb"`. Ветка `task/010`, бинарник уже собран:
`/Volumes/tera/сс/dispatcher/worktrees/010/target/release/rcdesk-host`
(`rcdesk-host 0.2.2 (dev)`, коммит `536ac04`). Ничего не подписано и не
установлено, `/Applications/rcdesk.app` не тронут.

Сейчас на Mac работает установленный агент в полном режиме (системный
LaunchAgent `/Library/LaunchAgents/app.rcdesk.agent.plist`, задание
`gui/501/app.rcdesk.agent`, `KeepAlive`). Его **останавливать не нужно**:
см. вариант А.

## Вариант А (рекомендую): установленный агент работает, тестовый хост рядом

Тестовый хост запускается с отдельным `HOME`, поэтому у него своё
устройство (`device.json` в `/tmp/rcdesk-d76/home/...`), свой PIN и свой лог.
Боевые `device.json`/`access.json` и запись Mac в аккаунте не меняются.
Если тестовый хост упадёт, Mac по-прежнему доступен через установленный
агент из списка «Мои компьютеры».

Запускать **из терминала PyCharm**: у PyCharm есть «Запись экрана» и
«Универсальный доступ», процесс из его терминала их наследует. Свежий бинарник
из Terminal.app или по двойному клику разрешений не получит: будет
`no capturable display found`.

1. Подключиться к Mac как обычно (установленный агент), открыть терминал PyCharm.
2. Запустить тестовый хост (одной командой; лог идёт и в терминал, и в файл):

   ```
   mkdir -p /tmp/rcdesk-d76/home && HOME=/tmp/rcdesk-d76/home RUST_LOG=info,rcdesk_host::signaling=debug /Volumes/tera/сс/dispatcher/worktrees/010/target/release/rcdesk-host serve --server wss://rcdesk.app/ws --name d76-test 2>&1 | tee /tmp/rcdesk-d76/agent.log
   ```

   Через пару секунд в терминале появится строка `PIN: NNNNNN`. Запомнить PIN.
3. Отключиться от установленного агента (Disconnect во вкладке). Иначе два
   сеанса делят канал, и цифры REMB будут неверными.
4. В Chrome открыть https://rcdesk.app, ввести PIN, «Подключиться». Плашку
   «Обновить хост», если появится, игнорировать.
5. 3–5 минут обычной работы, по минуте на каждое:
   - двигать и ресайзить окна, листать длинную страницу;
   - видео во весь экран (YouTube или любое);
   - статичный экран (ничего не трогать);
   - снова окна/скролл.

   Если есть возможность, на минуту нагрузить канал клиента (скачать большой
   файл на клиентской машине): тогда видно, режет ли контроллер по REMB.
6. Завершить: Disconnect во вкладке, затем подключиться к Mac через
   установленный агент (список «Мои компьютеры»), в терминале PyCharm нажать
   `Ctrl+C`. Возвращать ничего не нужно: установленный агент не
   останавливался.
7. Сообщить диспетчеру, что сеанс прошёл, и примерное время. Лог лежит в
   `/tmp/rcdesk-d76/agent.log`; он нужен до разбора (`/tmp` чистится при
   перезагрузке, поэтому до разбора Mac не перезагружать или скопировать лог,
   например в `~/rcdesk-d76-agent.log`).

Если ввод мышью/клавиатурой мешает или PyCharm без «Универсального
доступа», добавить `--no-input` в конец команды: картинка будет, ввода нет,
для замера REMB это не важно.

## Вариант Б: вместо установленного агента (только если владелец у Mac)

Нужен, только если нужен боевой `device.json` (Mac в списке аккаунта).
**Рвёт удалённый доступ**: выполнять, только сидя за самим Mac.

- Остановить установленный агент (без этого `KeepAlive` поднимет его снова):

  ```
  sudo launchctl bootout gui/501/app.rcdesk.agent
  pgrep -lx rcdesk-agent    # должно быть пусто
  ```

- Запустить тестовый хост с обычным `HOME` из терминала PyCharm:

  ```
  RUST_LOG=info,rcdesk_host::signaling=debug /Volumes/tera/сс/dispatcher/worktrees/010/target/release/rcdesk-host serve --server wss://rcdesk.app/ws 2>&1 | tee /tmp/rcdesk-d76/agent.log
  ```

  (перед этим `mkdir -p /tmp/rcdesk-d76`). Подключение по PIN или из списка,
  шаги 4–5 из варианта А.
- Вернуть установленный агент: `Ctrl+C` в терминале, затем

  ```
  sudo /Applications/rcdesk.app/Contents/MacOS/rcdesk-host fullmode restore
  launchctl print gui/501/app.rcdesk.agent | grep -E 'state|pid'   # state = running
  ```

  Если `restore` напишет, что задание пустое, а процесс жив вне launchd, он
  сам напечатает готовую команду `pkill -x rcdesk-agent && launchctl kickstart ...`.

## Разбор лога (только чтение)

```
python3 -I /Volumes/tera/сс/dispatcher/worktrees/010/docs/d76-log-summary.py /tmp/rcdesk-d76/agent.log
```

Фильтр по времени: `--from 2026-10-23T11:00 --to 2026-10-23T11:10` (UTC, как в
логе). Скрипт печатает отправленный битрейт, цель и REMB (распределения,
доля ниже пола 50, отношение REMB/отправлено и доля ниже 0,9), fps кодера,
ключевые кадры и PLI/FIR, RTT/jitter/потери, путь ICE, состояния
PeerConnection и решения adapt по причинам, частоту `reason="remb"` и число
переходов `probe → remb` («пила»). IP-адреса не печатает.

Чего ждём:

- **D76 работает:** `remb_kbps` есть почти в каждой сводке, медиана заметно
  выше 50, на ненагруженном канале REMB не ниже отправленного (отношение ≥ 1).
- **Пороги нормальные:** `reason="remb"` редко (меньше ~1 в минуту) и в
  основном при нагрузке канала, «зубцов» мало.
- **Повод пересмотреть пороги** (`REMB_CONGESTION_RATIO`, `REMB_IGNORE_BELOW_KBPS`):
  частые `remb` на ровном канале, REMB/отправлено стабильно чуть ниже 0,9.

Для сравнения, лог Windows-хоста пользователя на 0.2.1 (без abs-send-time,
сеанс 2026-10-23): медиана REMB 7 кбит/с, 60% сводок ниже пола,
`reason="remb"` 0,9 в минуту, 19 зубцов.
