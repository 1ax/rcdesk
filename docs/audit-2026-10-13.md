# Аудит rcdesk — 2026-10-13

Read-only проверка на коммите `9776f7d`: безопасность, узкие места, отказоустойчивость.
Пять направлений (сервер, хост, веб-клиент, инфраструктура/CI, видеопуть), ключевые
находки сверены архитектором по коду. Известные долги (D17, D22, D39, D40/D44/D48 и пр.)
не повторяются как новые, но упомянуты там, где находка их усиливает.

Критических находок (удалённый RCE, обход аутентификации, SQL-инъекции, XSS) нет.
Ниже — по убыванию серьёзности, с привязкой к коду.

## 1. Высокий приоритет

### S-H1. Сервер: OOM одним сообщением (DoS)
`server/src/ws.rs:47-61` — `WebSocketUpgrade` без `max_message_size`/`max_frame_size`,
дефолт tungstenite 64 MiB / 16 MiB. `ws.rs:66` — `mpsc::unbounded_channel`.
Неаутентифицированный клиент шлёт один `Offer` на 64 МБ: разбор + клон в канал пира +
сериализация ≈ 200 МБ при лимите контейнера 256M → OOM-kill → все хосты отваливаются.
Второй вектор: клиент, не читающий сокет, копит сообщения пира в канале без предела.
**Фикс:** `ws.max_message_size(64*1024).max_frame_size(64*1024)`; `mpsc::channel(64)` +
`try_send`, при `Full` закрывать соединение; cap длины `name`/`alias`.

### S-H2. Сервер: неаутентифицированный рост SQLite
`devices.rs:60-68` — `HostRegister{device: None}` вставляет строку `devices` на каждое
соединение, устройства не чистятся. `ws.rs:610-634` — `ClientAuth{token: None}` в цикле на
одном соединении: каждое — новый владелец + токен. Prune — только владельцы, раз в сутки,
через 30 дней.
**Фикс:** `ClientAuth` не более одного раза на соединение; лимит новых регистраций по IP
(паттерн `PinLimiter`); prune устройств без `ownership` старше N дней.

### S-H3. TURN: креды без аутентификации, TTL 24 ч, relay на внутренние адреса
`ws.rs:253-258` — `Registered` с TURN-кредами для любого `HostRegister` без кредов;
`ice.rs:18` TTL 86400. `infra/docker-compose.prod.yml:41-57` — coturn в `network_mode: host`
без `--denied-peer-ip`, `--no-tcp-relay`, `--user-quota`, `--total-quota`. Любой получивший
креды проксирует через coturn на `127.0.0.1:8100` (сигналинг в обход nginx →
подделка `X-Real-IP`, `ws.rs:31-38` → обход лимита PIN), на `127.0.0.1:9641`, на соседние
порты VPS и в сеть провайдера. Файрвола на VPS нет.
**Фикс:** `--denied-peer-ip` для 127/8, 10/8, 172.16/12, 192.168/16, 169.254/16, `::1`,
`fc00::/7` и внешнего IP; `--no-tcp-relay`; квоты; TTL 1–2 ч; TURN не выдавать в
`Registered` (только STUN — хост получает свежие креды в `PeerJoined`); в сервере доверять
`X-Real-IP` только при loopback-пире.

### S-H4. PIN: статичный, оракул «host busy», IPv6
`registry.rs:159-164` — PIN живёт весь аптайм хоста (D44). `ws.rs:941-944` — токен лимита
тратится только на `UnknownPin`: ответ `host busy` бесплатно подтверждает верный PIN
занятого хоста. `pin_limit.rs:36` — ведро по полному `IpAddr`: /64 IPv6 даёт бесконечные
свежие ведра. Успешный `Join` даёт постоянную привязку (`ws.rs:928-935`), без пароля на
хосте PIN — единственный барьер.
**Фикс:** ротация PIN после каждого успешного `Join` и по TTL 10 мин (закрывает D44, нужно
сообщение хосту с новым PIN); любой `Err` из `join` — попытка; ключ ведра для v6 — /64;
глобальное ведро как второй контур.

### H-H1. Хост MF async-MFT: гонка кредитов (вероятная причина D58)
`host/src/encode/mediafoundation.rs:491-503`:
```rust
self.drain_events_no_wait()?;
if self.credits == 0 { self.wait_for_event()?; }
unsafe { self.transform.ProcessInput(0, &sample, 0) }...
```
`wait_for_event` (:527-536) обрабатывает ровно одно событие; `handle_event` (:544-551)
даёт кредит только на `METransformNeedInput`. Если событием оказался
`METransformHaveOutput` (у аппаратных MFT выход кадра n приходит раньше следующего
`NeedInput`), `credits` остаётся 0, `ProcessInput` всё равно вызывается →
`MF_E_NOTACCEPTING` → поток кодера выходит. В 0.1.0–0.1.2 — молча, ровно картина
«застывает через несколько секунд». Плюс `GetEvent(MF_EVENT_FLAG_NONE)` без таймаута (D17).
**Фикс (~25 строк):** `while self.credits == 0 { wait_one_event_with_deadline()? }`,
ожидание через `MF_EVENT_FLAG_NO_WAIT` + `sleep(1 ms)` с дедлайном 1–2 с → `Err` (уйдёт в
D58-путь). Проверка: лог второго пользователя на `MediaFoundation ProcessInput (async)`.

### H-H2. Windows полный режим: DACL без смены владельца
`platform/windows/service.rs:225-232` (`create_dir_all` — no-op, если каталог есть) и
`:279-289` — `SetNamedSecurityInfoW` только с `DACL_SECURITY_INFORMATION`. Локальный
не-админ, заранее создавший `C:\ProgramData\rcdesk`, остаётся владельцем (неявный
WRITE_DAC), после установки возвращает себе права и читает `device.json`, `pin.txt`,
подменяет `access.json`.
**Фикс:** передать `OWNER_SECURITY_INFORMATION` с SID Administrators (включив
`SeTakeOwnershipPrivilege`), либо отказывать в установке, если каталог существует с чужим
владельцем.

### I-H1. Бэкапа БД нет, а в ней уже passkey и аккаунты
Решение «бэкап не делаем» (ARCHITECTURE §6, 3.1) принималось до 3.7. Теперь потеря тома =
57 владельцев теряют кабинеты и passkey (discoverable credential привязан к user handle в
БД, по PIN не восстанавливается). Единственный бэкап — ручной `pre37`. Сервер не делает
`wal_checkpoint`, SIGKILL на деплое — WAL обязателен в бэкапе.
**Фикс:** cron под `rcdesk` раз в сутки через `docker run --rm -v rcdesk_db-data:/data
alpine` + `sqlite3 .backup`, ротация 14 дней, копия offsite. Записать в ARCHITECTURE §11.

### I-H2. Ключ подписи релизов: `secrets: inherit`, нет ротации, нет свежести манифеста
`release.yml:26`, `deploy.yml:76` — `secrets: inherit` в `build-host.yml`, хотя нужны только
`MACOS_*`. Публичный ключ зашит (`update_verify.rs:21`), процесса отзыва нет (README:137).
Компрометация GitHub-аккаунта = подписанный манифест → установка с правами root/admin на
всех хостах. Манифест без `issued_at`: подменой ответа можно вечно отдавать старую
подписанную версию (freeze). Даунгрейд закрыт (`updater.rs:178`).
**Фикс:** явные `secrets:` в `build-host`; GitHub Environment `release` с required
reviewer; `key_id` в манифесте и два зашитых ключа (резервный приватный — офлайн);
`issued_at` с отказом старше N дней.

## 2. Средний приоритет

### Сервер
- **Несколько сеансов на одного клиента.** `registry.rs:264-301` `join_by_host_id` не
  проверяет, что `client_tx` уже в сеансе; `:399-405` `disconnect_client` снимает только
  первый. Остальные хосты остаются `busy` до своего `Bye`; задача writer и половина
  сокета утекают. Фикс: `AlreadyInSession` + `retain`.
- **`register_host` может снести чужой сеанс.** `registry.rs:146-151` — удаление
  `old.session_id` без фильтра `host_id` (в `unregister_host` он есть). Нужен чужой `sid`
  (82 бита, но пишется в лог на info). Фикс: фильтр.
- **SQLite:** `synchronous=FULL` + fsync под std-мьютексом на воркерах tokio; нет
  `busy_timeout` (`db.rs:85`) — открытый `sqlite3` владельца = `internal error` всем.
  Фикс: `synchronous=NORMAL`, `busy_timeout(2s)`.
- **Отравленный мьютекс при зелёном healthz.** `.lock().expect(...)` повсюду, `/healthz`
  (`app.rs:38-40`) не трогает ни БД, ни реестр. Фикс: healthz делает `SELECT 1` +
  `registry.lock()`.
- **Нет серверных Ping и таймаута чтения** (`ws.rs:109-136`): хост с пропавшей сетью
  остаётся `online`. Фикс: Ping раз в 30 с, закрытие после двух пропущенных Pong.
- **Нет graceful shutdown** на SIGTERM (`main.rs:47-52`); passkey-state без TTL и без
  `owner_id` (`ws.rs:714`, `:600`); `/ws` не проверяет `Origin`.

### Хост
- **`connect` без таймаута** (`signaling/mod.rs:353`, `:376`): висящий accept без ответа
  замораживает `run_agent` навсегда. Фикс: `timeout(30s)` в `app.rs:517-523`.
- **Остановка конвейера на macOS блокируется до изменения экрана.**
  `pipeline/mod.rs:460-468` `join` capture-потока, который стоит в `rx.recv()` scap; SCK
  на статичном экране ничего не отдаёт, `stop_capture` — только в `Drop` после join.
  Каждый конец сеанса / `SelectDisplay` / `SetCurtain` течёт потоком blocking-пула и живым
  SCK-стримом. Фикс: явный `stop()` у `FrameSource` до join; rate-limit `SelectDisplay`.
- **Нет watchdog «кадры не идут».** D58 ловит `Err`, не зависание: молчащий источник
  даёт вечный keyframe из `last_raw` (`pipeline/mod.rs:293-337`). Фикс: подписка на
  реконфигурацию дисплеев + пересборка через `replace_pipeline`; детектор
  «captured растёт, encoded нет N с».
- **Привязка DTLS берёт только первую `a=fingerprint`** (`dtls_bind.rs:43-61`,
  `web/src/dtlsBind.ts:16-29`). По RFC 8122 медиа-уровень перекрывает сессионный: MITM на
  сигналинге оставляет подлинный отпечаток на session-level, свой — в m-секции; Chrome
  применит медиа-уровень. На хост не проходит (`rtc` отвергает конфликт), на клиент —
  проходит. Фикс: собирать все строки, `None` при расхождении; при ошибке `set_answer`
  слать `Bye`.
- **Шторка снимается даже при неудачной блокировке** (`signaling/mod.rs:1061-1078`):
  `lock_screen()` → `Err` → `hide()` всё равно → рабочий стол открыт. Фикс: не снимать без
  подтверждения `screen_is_locked()`.
- **Junction-гонка в машинном режиме** (`files/mod.rs:353-390`): помощник SYSTEM создаёт
  вложенные папки в `Downloads` пользователя, проверка `starts_with` лексическая. Фикс:
  имперсонация токена консольного пользователя на время файловых операций.
- **PIN в логе на `info`** (`app.rs:527-531`); `Debug` сигнальных сообщений может
  напечатать `device.secret` при повторном `Registered` (`signaling/mod.rs:391-394`).
- `ws://` принимается для не-loopback (`main.rs:69`); `active.written + len` без
  `checked_add` (`files/mod.rs:460`); нет лимита размера принимаемого файла и проверки
  места; `desktop.ini`/`.lnk` проходят санитайзер; потоки cursor/clipboard/InputRouter
  умирают молча (помимо D58).

### Веб-клиент
- **Нет CSP и security-заголовков** (`index.html`, nginx вне репо). Токен в `localStorage`:
  любой будущий XSS = кража аккаунта. Фикс: meta-CSP `default-src 'self'; script-src 'self'
  'wasm-unsafe-eval'; connect-src 'self'; img-src 'self' data: blob:; object-src 'none';
  base-uri 'none'`; в nginx HSTS, `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy`.
  Сниппет nginx положить в `infra/` как источник правды.
- **Даунгрейд DTLS-привязки.** `app.ts:2302` — проверка только если в этом сеансе прошёл
  OPAQUE. Сервер-в-середине не пересылает `auth_required` и шлёт свой `offer` с
  `auth: null` — клиент примет. Фикс: флаг «хост требует пароль» по `device_id` в
  `localStorage`, отклонять `offer` без OPAQUE для такого устройства; дальше — TOFU
  отпечатка.
- **Буфер обмена без жеста и индикации.** `clipboard.ts:147` пишет в буфер владельца на
  каждый `clipboard_text` с хоста; в Chrome `clipboardchange` (`app.ts:2135`) отправляет
  каждое локальное копирование (пароль из менеджера) на хост. Фикс: opt-in чекбокс для
  автосинхронизации, заметка «буфер обновлён с хоста».
- **`offer`/`ice` не сверяют `session_id`** (`app.ts:2277`, `:2347`), после `await` нет
  проверки `session === currentSession` — запоздалый offer старого сеанса ломает новый.
- **Приём файлов в память без лимита в `onStart`** (`fileTransfer.ts:488-493`, `:503`,
  `:514`): лимит 2 ГиБ считается только по офферу; хост может лить до OOM вкладки. Фикс:
  сверять `size` с остатком бюджета, снизить лимит или писать через `showSaveFilePicker`.
- **Восстановление без таймаута** (`app.ts:1959-1972`): потерянный ответ на
  `connect_device` = вечный баннер «Переподключение… (1 из 5)». **Повторный `joined`** не
  закрывает текущий сеанс (`app.ts:2083-2150`) — два клика по разным устройствам = два
  `PeerConnection`.
- Имя события = строка от сервера (`signaling.ts:65-71`, `{"type":"close"}` коллидирует с
  внутренними); guard от устаревшего pc только в одном колбэке; реконнект без потолка.

### Инфраструктура и CI
- **Docker:** нет `logging` с ротацией (логи `wrong pin` и coturn растут без предела),
  нет `cap_drop`/`read_only`/`no-new-privileges`, образы без дайджеста, `coturn/coturn:4`
  плавающий; `cargo build` без `--locked` (`Dockerfile:28`).
- **Workflows:** нет `permissions:` на верхнем уровне, actions по тегам, не по SHA;
  `ssh-keyscan` TOFU на каждом прогоне (`deploy.yml:98-99`); образ на сервере по `latest`
  — отката на предыдущий sha нет; `--remove-orphans` (прецедент D25).
- **Мониторинг:** только трафик в Telegram. Нет внешнего пинга `/healthz`, алерта на
  coturn down, диск, сертификат. Фикс: UptimeRobot/healthchecks.io + `df` в тот же бот.
- **Supply chain:** `cargo audit`/`cargo deny` не установлены и не в CI; Dependabot нет;
  `npm audit` — 1 high (dev-only, `source-map-js`); вендорный `rtc-sctp` без процесса
  синхронизации с upstream.
- nginx-конфиг вне репо (FastPanel), D39 (`Cache-Control`) открыт.
- Установщики без подписи/нотаризации — принято (ARCHITECTURE §9); TOCTOU между проверкой
  sha256 и запуском `.pkg` с правами администратора (`updater.rs:186-199`) — низкий.

### Видеопуть (производительность)
- **Нет пейсинга RTP** (`transport/mod.rs:864-873`): IDR 126–322 КБ уходит залпом
  110–270 пакетов. На Wi-Fi/TURN: потери → PLI → новый IDR → цикл; GCC Chrome режет REMB.
  Квик-вин: `sleep(1 ms)` каждые ~16 пакетов; настоящий фикс — токен-пейсер.
- **Windows BGRA→NV12: 5 копий и 2 аллокации по мегабайтам на кадр** (scap `to_vec`,
  `convert.rs:85-94` ×3, `:138-156` скалярный interleave, `mediafoundation.rs:301-322`).
  Фикс (~60 строк): прямой проход в залоченный `IMFMediaBuffer` со scratch-буферами;
  ожидание −3…6 мс/кадр на Ivy Bridge.
- **VideoToolbox:** `CVPixelBufferCreate` на каждый кадр без пула (`videotoolbox.rs:515-524`);
  второй выход за `encode()` выбрасывается (`:456-463`) — рвёт цепочку ссылок до PLI.
- **IDR каждые 10 с** (`signaling/mod.rs:651`) при наличии PLI/NACK — ~250 кбит/с и залп
  впустую; поднять до `fps*60`.
- **openh264 однопоточный** (`openh264.rs:57-68`: `num_threads(0)` при одном слайсе);
  slice-mode даст 2–3× на fallback-пути (CI/VM/Win без MF).
- **Адаптация:** `last_loss` никогда не затухает (`adapt/mod.rs:438`) — при пропаже RR
  режет до пола; RTT/jitter считаются, но не используются.
- **Диагностика:** хост не логирует сводку сеанса (fps захвата, encode ms avg/p95,
  битрейт, drops) — нечем разбирать D58/D59 по логам. Квик-вин: `info!` раз в 5 с в
  `run_adapt_task`.
- GDI: две лишние копии 8 МБ на кадр (`gdi.rs:239-240`); WGC на статике не дедупится
  (проверить `bench --capture wgc` на статике); `[profile.release]` без LTO.
- Клиент: `jitterBufferTarget` не задан (Chrome держит адаптивный буфер 12–149 мс).

## 3. Что сделано хорошо
- Серверные типы не инжектируются, пересылка пересобирается из полей; принадлежность
  сеанса проверяется по идентичности канала и `host_id`+`session_id`.
- CSPRNG, токены ≥ 222 бит, в БД только SHA-256, все SQL параметризованы, каскады, миграции
  с `foreign_key_check`, отзыв токена действует со следующего сообщения.
- OPAQUE: сьют закреплён тестом, `0600` атомарно, pace-limit переживает реконнект; DTLS
  HMAC в константное время, отсутствие тега при пароле → `Bye`.
- Самообновление: ed25519 до разбора JSON, sha256 ассета, строгое `version > current`,
  `--proto =https`, `RunGuard`.
- Файлы: `create_new`, санитайзер, ссылки не следуются, part-файл чистится в `Drop`,
  backpressure. Клиент: XSS нет, таймеры и слушатели чистятся, proto-дрейф ловится в CI.
- Windows-служба: Job `KILL_ON_JOB_CLOSE`, супервизор с backoff, `validate_server`, нет
  IPC-поверхности.
